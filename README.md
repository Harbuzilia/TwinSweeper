# TwinSweeper — Pro Disk Optimizer v3.7

Настольное приложение для Windows (Python + [Flet](https://flet.dev)) для поиска и
безопасного удаления дубликатов файлов, похожих изображений и накопившегося мусора.

## Возможности

- **Поиск дубликатов** — многопоточное сканирование выбранных дисков/папок.
  Турбо-режим (быстрый хэш + обязательная проверка полным SHA-256 при совпадении),
  фильтры по размеру (мин/макс, КБ) и маскам имён, SQLite-кэш хэшей (WAL) для мгновенного пересканирования,
  живой прогресс со скоростью и ETA.
- **Похожие фото** — перцептивные хэши (dHash) с учётом EXIF-ориентации:
  находит визуально похожие изображения даже с разными именами и размерами.
  Ничего не предвыделено к удалению — похожие ≠ дубликаты.
- **Умное автовыделение** — одним правилом: «оставить новейший / старейший /
  максимальное разрешение / копию из приоритетной папки», с защитой
  «в каждой группе останется хотя бы одна копия».
- **Приоритетные папки** — «держать файлы из D:\Photos, чистить остальные»
  (сохранённый список, редактор прямо из результатов).
- **Поиск по образцу** — «найди все копии этого файла» по полному хэшу с префильтром по размеру.
- **Сравнение папок** — уникальные файлы каждой стороны + общие (без учёта регистра имён),
  с бейджами «новее»/«больше».
- **Клинер мусора** — пустые папки (вложенные деревья удаляются за один проход),
  битые ярлыки (.lnk, системная кодировка), файлы мусора; отмена сканирования.
- **NTFS-хардлинки** — замена дубликатов жёсткими ссылками без потери путей (только для
  байтово-идентичных файлов, с откатом при сбое).
- **Переместить в папку** — обратимая альтернатива удалению: атомарное копирование
  (файл-источник удаляется только после полной копии), без перезаписи существующих,
  с возможностью отмены из журнала.
- **Опустевшие папки** — опция «удалять опустевшие папки» после удаления/перемещения:
  только `os.rmdir` (папка с любым содержимым не трогается), отмена перемещения
  воссоздаёт удалённую папку.
- **Безопасность данных**: подтверждение перед каждой операцией, опция «в корзину»
  (сбой корзины никогда не превращается в безвозвратное удаление), журнал операций
  с отменой для удаления/хардлинков/перемещений, перепроверка файлов на момент
  операции (не удаляется «не тот» файл), защита групп от выделения целиком.
- **История и статистика** сканирований, экспорт результатов в CSV/JSON/TXT/HTML.
- Кэш миниатюр (160px) — списки фото не гоняют полноразмерные файлы в UI.
- Настройки (язык/тема/корзина по умолчанию) сохраняются между запусками;
  смена языка или темы не сбрасывает открытые результаты.
- Интерфейс **RU/EN** (включая сообщения ядра), тёмные/светлая темы.

## Гарантии корректности («не удалит не тот файл»)

Главный принцип — программа не может удалить или переместить файл, который не
является настоящим дубликатом. Это обеспечено многоуровнево и покрыто тестами:

1. **Содержимое проверяется полностью.** В турбо-режиме быстрый хэш (первые/последние
   64 КБ) только отбирает кандидатов; каждая группа затем подтверждается полным
   SHA-256 всех файлов. Совпал размер, но не содержимое — файлы НЕ дубликаты.
2. **Кэш хэшей не устаревает.** Хэш в кэше привязан к (размер, mtime) файла: если файл
   изменили, старый хэш сбрасывается и пересчитывается. Отредактированный файл не
   будет «подтверждён» как дубликат своего прежнего содержимого.
3. **Один физический файл не считается дубликатом.** Хардлинки, junction-алиасы и
   перекрывающиеся папки сканирования распознаются по (устройство, inode) — удаление
   «дубликата» не уничтожит «оригинал», потому что это один и тот же файл.
4. **Системное и корзина исключены.** `$Recycle.Bin`, `System Volume Information` не
   индексируются: удалённая ранее копия не может стать «оригиналом» и пометить живой
   файл «дубликатом».
5. **Перепроверка перед удалением (TOCTOU-защита).** Непосредственно перед удалением/
   хардлинком/перемещением файл сверяется со снимком скана (размер, mtime). Изменился
   — операция пропускается с ошибкой, файл остаётся.
6. **Группа не исчезает целиком.** Правила «выделить всё»/«инвертировать» и удаление
   гарантируют: в каждой группе остаётся минимум одна копия («оригинал» защищён).
7. **Корзина — значит корзина.** Если «удалить в корзину» выбрано, но корзина недоступна,
   файл НЕ удаляется (никакого тихого безвозвратного удаления). Сбой корзины = ошибка.
8. **Сканы без проверки содержимого** (только по размеру/имени) не предвыделяют файлы
   и показывают предупреждение.
9. **Похожие фото (pHash) — не дубликаты.** Они не предвыделяются к удалению, кнопка
   хардлинка скрыта, а кластеризация complete-linkage не сливает заведомо разные кадры.
10. **Каждая операция обратима.** Удаление/хардлинк/перемещение пишутся в журнал
    (`operations_log.json`) с возможностью отмены — даже если операция была прервана.

Остаточные ограничения честно описаны в [`AUDIT_REPORT.md`](AUDIT_REPORT.md)
(миллисекундное TOCTOU-окно, глубокие пути >260 символов зависят от настройки ОС).

## Требования

- Windows 10/11, Python 3.12+ (os.path.isjunction; проект собирается и тестируется на 3.14).
- Зависимости — в [`requirements.txt`](requirements.txt) (точные версии), dev-инструменты
  (pytest, ruff, pyinstaller) — в [`requirements-dev.txt`](requirements-dev.txt).

## Запуск

```bat
python -m venv venv
venv\Scripts\pip install -r requirements-dev.txt
venv\Scripts\python main.py
```

или просто `BUILD.bat` → пункт `[1] Run Application`.

В аргументах командной строки можно передать стартовые каталоги:
`python main.py D:\Photos E:\Backup`.

## Тесты и линт

```bat
venv\Scripts\python -m pytest tests/ -q
venv\Scripts\python -m ruff check .
```

Тесты полностью изолированы: работают только во временных каталогах pytest
(`tmp_path`) и перенаправляют рабочие данные через переменную окружения
`DUPLICATER_DATA_DIR` — реальные файлы пользователя не сканируются и не изменяются.

## Сборка портативного EXE

```bat
BUILD.bat
```
(пункт `[2] Build Portable EXE`) — эквивалентно команде:

```bat
venv\Scripts\python -m PyInstaller --noconfirm --onefile --windowed --collect-all flet --name TwinSweeper main.py
```

Готовый файл: `dist\TwinSweeper.exe` — работает на любом Windows-ПК без установленного Python.

## Где хранятся данные приложения

| Файл | Назначение |
|---|---|
| `scan_cache.db` | SQLite-кэш хэшей (ускоряет повторные сканирования) |
| `operations_log.json` | журнал операций удаления/хардлинков (основа для «Отменить») |
| `scan_history.json` | история сканирований |
| `twinsweeper.log` | журнал работы приложения (ротация ~1 МБ × 3) |

- При запуске из исходников — в каталоге проекта.
- В собранном EXE — `%LOCALAPPDATA%\TwinSweeper`.
- Переопределяется переменной окружения `DUPLICATER_DATA_DIR` (используется тестами).

## Структура проекта

```
main.py               — точка входа, окна/вкладки, фоновые воркеры
scanner.py            — сканирование, хэши, группы дубликатов, сравнение папок
phash_scanner.py      — перцептивные хэши изображений, кластеризация похожих
sweeper.py            — пустые папки, битые .lnk, файлы мусора
hardlink_manager.py   — NTFS-хардлинки с проверкой идентичности и откатом
db_cache.py           — потокобезопасный SQLite-кэш хэшей
ops_log.py            — журнал операций и отмена (delete/hardlink/move)
folder_priorities.py  — приоритетные папки для умного автовыделения
locales.py            — RU/EN переводы (включая сообщения ядра)
app_info.py           — имя/версия приложения (единый источник)
app_logging.py        — файловое логирование
ui/                   — представления Flet (search, results, sample, compare, sweeper, thumbnails)
tests/                — pytest-тесты (изолированные, tmp_path) + CI (.github/workflows)
```

Подробности проведённого аудита и статус всех найденных проблем — в [`AUDIT_REPORT.md`](AUDIT_REPORT.md);
история изменений — в [`CHANGELOG.md`](CHANGELOG.md).

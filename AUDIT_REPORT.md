## Гарантия сохранности ваших данных

Жёсткое условие аудита — **ничего не удалять с компьютера** — выполнено и проверено
контрольными суммами рабочих файлов до и после всех работ:

| Файл | MD5 до | MD5 после |
|---|---|---|
| `scan_cache.db` | `69a75273c06509fc08da2ad53cdcfdd2` | совпадает |
| `scan_cache.db-shm` | `b7c14ec6110fa820ca6b65f5aec85911` | совпадает |
| `scan_cache.db-wal` | `d41d8cd98f00b204e9800998ecf8427e` | совпадает |
| `operations_log.json` | `d751713988987e9331980363e24189ce` | совпадает |
| `scan_history.json` | `d751713988987e9331980363e24189ce` | совпадает |

Как это обеспечено: каждый тест работает только во временных каталогах pytest (`tmp_path`);
`tests/conftest.py` задаёт `DUPLICATER_DATA_DIR` **до** импорта модулей проекта, так что
кэш, журнал операций и история всегда указывают на временные копии. Ни один тест
не сканирует реальные диски и не трогает реальные файлы.

## Часть 1. Исправленные проблемы

### Критические (риск потери данных)

**C1 — Хардлинк визуально похожих фото терял контент.**
`hardlink_manager.py` / `ui/results_view.py`.
Результаты поиска похожих изображений (pHash) открывались в том же экране результатов
с активной кнопкой хардлинка, а `replace_with_hardlink` не проверял байтовую
идентичность: похожая (но другая!) фотография заменялась ссылкой на оригинал —
безвозвратно.
*Фикс (двухслойный):* (1) `ResultsView` получил флаг `allow_hardlink=False` для
pHash-результатов — кнопка скрыта; (2) в `replace_with_hardlink` перед заменой
обязательная проверка: совпадение размера **и** полного SHA-256, иначе отказ
с объяснением. *Тесты:* `tests/test_hardlink_manager.py` (отказ при разных
размерах/контенте), `tests/test_results_view.py` `TestHardlinkVisibility`.

**C2 — TOCTOU: удаление/хардлинк без перепроверки файла.**
`ui/results_view.py` / `main.py`.
Пути брались из моментального снимка сканирования: если файл менялся между сканом
и удалением — операция действовала на «уже не тот» файл.
*Фикс:* `ResultsView` передаёт кортежи `(path, size, mtime)` из `FileInfo`
(`get_selected_entries`); воркер перед `os.remove`/`send2trash`/хардлинком сверяет
актуальные size/mtime через `verify_file_unchanged` (main.py) — при расхождении файл
пропускается и попадает в список ошибок. *Тесты:* `tests/test_main.py`
`TestVerifyFileUnchanged` (5 тестов: неизменённый проходит, изменение размера/mtime/
пропажа файла — отказ с причиной).

**C3 — «Выделить всё»/«Инвертировать» стирали группу целиком.**
`ui/results_view.py`.
Правила `all`/`invert` выделяли и «оригинал» группы → подтверждение удаляло все копии.
*Фикс:* гард `_protect_originals` — в группах, где выделены все файлы, автоматически
защищается один («оригинал»); диалог подтверждения показывает количество таких
«групп под защитой». *Тесты:* `tests/test_results_view.py` `TestProtectOriginals`
(5 тестов, включая инверсию и частичное выделение).

### Высокие

**H1 — Вкладка «Общие файлы» падала с KeyError.**
`ui/compare_view.py` / `scanner.py`.
`compare_folders` возвращает ключи `file_a/file_b/similarity/newer/larger`, а вью
читал `name/path_a/path_b/size` — сравнение папок в UI валилось.
*Фикс:* вью приведён к реальной схеме (бейджи «новее»/«больше» уже были в данных).
*Тесты:* тесты схемы `compare_folders` в `tests/test_scanner.py`.

**H2 — Fallback при ошибке сравнения имел несовместимую схему.**
`main.py`.
При ошибке сравнения папок возвращалась структура с чужими ключами → KeyError,
поток умирал, прогресс висел.
*Фикс:* `EMPTY_COMPARE_RESULT` — зеркало реальной схемы
(`unique_a/unique_b/common/total_files`); ошибка показывается в UI.
*Тесты:* `tests/test_main.py` `TestCompareFallbackSchema` (ключи и пустота значений).

**H3 — Фоновые воркеры теряли контекст страницы.**
`main.py`.
Воркеры запускались через «сырой» `threading.Thread` без контекста flet — обращения
к `page`/диалогам из потока ненадёжны (след отладки `_probe_fp.py` это подтверждал).
*Фикс:* все 5 воркеров сканирования/удаления/хардлинка/отмены и undo переведены на
`page.run_thread(...)`, который в flet 0.86.5 восстанавливает контекст страницы.
*Тесты:* headless-тесты вью (`tests/test_sweeper_view.py` и др.) + import-smoke.

**H4 — «Очистка мусора» удаляла навсегда без подтверждения.**
`ui/sweeper_view.py` / `sweeper.py`.
Клик по «Очистить» сразу безвозвратно удалял файлы; `desktop.ini` считался мусором
(это легитимный файл настройки папок Windows).
*Фикс:* диалог подтверждения (количество, иконка, красная кнопка), опция
**«в корзину»** (по умолчанию включена, для файловых режимов); пустые папки удаляются
только `os.rmdir` (физически не может удалить непустую); операция журналируется в
`operations_log.json`; не удалённое остаётся в списке для повтора; `desktop.ini`
убран из `JUNK_FILENAMES` (sweeper.py:9). *Тесты:* `tests/test_sweeper_view.py`
`TestConfirmationDialog`, `TestEmptyFolderDeletion`.

**H5 — Сбой корзины молча превращался в безвозвратное удаление.**
`main.py` (delete_files_handler) / `ui/sweeper_view.py` (execute_clean).
Если `send2trash` падал, код переходил к `os.remove` — файл терялся навсегда вместо
того, чтобы остаться.
*Фикс:* при сбое корзины файл **не удаляется**, ошибка пишется в список и показывается
пользователю; fallback на `os.remove` отсутствует физически.
*Тесты:* `tests/test_sweeper_view.py` `test_failed_trash_keeps_file`.

## Часть 3. Что осталось (15 позиций + рекомендации)

Приоритет — по вашему выбору «крит/высок/средние сейчас»: всё, что не могло
повлечь потерю данных или падение, отложено. Отсортировано по полезности.

### Средние (2)

1. **M11 — Выбор «оригинала» группы произволен.** `ui/results_view.py`
   (`select_default_duplicates` — «первый по порядку обхода») и
   `hardlink_manager.batch_replace_with_hardlinks` (group[0]). Рекомендация:
   выбирать оригинал по явному правилу (старейший mtime / самый длинный путь
   «первичный» каталог) и показывать его пользователю бейджем.
2. **M12 — Пустые файлы в особых режимах.** Обычный поиск дубликатов уже пропускает
   пустые файлы по умолчанию (`ignore_empty_files=True` + чекбокс в UI). Осталось:
   pHash/поиск-по-образцу не имеют такого фильтра; группы из 0-байт файлов не дают
   экономии при хардлинке (freed = 0) — можно не предлагать их к хардлинку вовсе.

### Низкие (13)

3. **MAX_PATH > 260 символов.** Ни `scanner.py`, ни `sweeper.py` не используют префикс
   `\\?\` — глубокие деревья упираются в лимит Win32. Рекомендация: оборачивать пути
   для `os.*` вызовов и включить `manifest` `longPathAware` для EXE.
4. **Хардкод английских строк в `hardlink_manager.py`** (сообщения
   «Original file not found…» и т.п.) показываются пользователю в диалогах ошибок —
   в обход i18n. Рекомендация: вернуть коды ошибок, переводить в `locales.py`.
5. **Версия зашита в UI-строку.** `main.py:947` — `ft.Text("v3.5")`. Рекомендация:
   константа `APP_VERSION` в одном месте (+ подстановка в заголовок окна и About).
6. **CI нет.** Рекомендация: GitHub Actions — `pytest` + `ruff check` на push;
   всё уже готово к запуску одной командой.
7. **Типизация/mypy нет.** Код местами типизирован — `mypy --strict` нереален, но
   прогон по базовым правилам выявит регрессии. Начать с `scanner.py`/`ops_log.py`.
8. **pHash: BK-tree.** Кластеризация теперь прекомпилирована (M4), но всё ещё
   попарная — O(n²). Для библиотек 100k+ изображений — BK-tree/LSH-индекс.
9. **`os.startfile` не на всех платформах** — приложение Windows-only, но вызовы без
   guards (`ui/results_view.py`) — при портировании сломаются.
10. **`operations_log.json` без ротации/размера** — `MAX_OPERATIONS = 100` есть,
    но файл переписывается целиком при каждой операции; при частых операциях — лишний IO.
11. **Кэш-промахи не различаются от ошибок** в статистике `db_cache` — после
    сегодняшнего логирования (DEBUG) диагностика возможна, но счётчиков нет.
12. **`compare_folders` не кэшируется** — повторное сравнение тех же папок
    пересчитывает хэши заново.
13. **Отсутствует graceful shutdown воркеров** — отмена есть, но поток сканирования
    при закрытии окна не джойнится (daemon=True спасает от зависания, но операция
    может оборваться на середине записи кэша).

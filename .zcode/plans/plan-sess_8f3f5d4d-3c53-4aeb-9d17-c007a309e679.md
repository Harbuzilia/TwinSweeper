# Раунд 3: корректность «не удалит не тот файл» + закрытие проекта. Тесты — только настоящие

Принцип тестирования (твоё требование): каждый новый тест — РЕАЛЬНЫЙ регрессионный, обязан падать при откате фикса и проверять наблюдаемое поведение (содержимое файлов, структуру результата), а не моки. Без погони за количеством. Существующие 299 тестов проходят ревизию: фейковые/тавтологические/слабые — удаляются или переписываются (аудит-агент уже запущен). Данные пользователя не трогаем; чексуммы до/после; коммит после каждого блока.

## Блок A — КРИТИЧЕСКОЕ: корректность определения дубликатов
1. **Кэш хэшей (главная дыра, подтверждена чтением SQL).** `COALESCE` в `save_file_hash` сохраняет устаревший `full_hash` при записи turbo-хэша с новыми size/mtime → фаза SHA-256-верификации «подтверждает» отредактированный файл как дубликат своего же старого содержимого → предвыделение → удаление уникального файла. Фикс: `CASE WHEN size/mtime изменились THEN NULL`; `get_file_hash(turbo=True)` не возвращает full_hash. **E2E-тест**: два идентичных файла → скан (кэш) → правка «середины» одного (размер и первые/последние 64 КБ те же, mtime новее) → повторный turbo-скан НЕ должен их сгруппировать. Тест падает на старом коде.
2. **Один физический файл ≠ «дубликаты».** Индексация по `(st_dev, st_ino)` (guard: st_ino != 0): хардлинки, junction-алиасы, перекрывающиеся корни скана не дают фантомных групп, где удаление «дубликата» уничтожает «оригинал». Тесты: реальный `os.link` → не группируются; junction на внешнюю папку → её файлы не индексируются.
3. **Системный мусор.** `$Recycle.Bin`/`System Volume Information` вырезаются на обходе (копия из корзины не становится «оригиналом»); в directory-junctions не спускаемся (циклы/двойной обход). Тест: файл в `$Recycle.Bin` не попадает в результаты.
4. **«В корзину» без send2trash.** `use_trash=True` и нет библиотеки → ошибка+пропуск, НИКАКОГО тихого `os.remove`; чекбокс корзины в ResultsView дизейблится при недоступности. Тест: monkeypatch HAS_SEND2TRASH=False → файл цел, ошибка в state.
5. **Сканы без проверки содержимого** (только размер/имя): никакого предвыделения + баннер «содержимое не проверялось». Флаг `content_verified` из run_scan в ResultsView. Тест: by_hash=False → selected_paths пуст.
6. **Отмена середины операции теряет журнал.** `return state` в perform_* до журналирования → уже удалённое/перемещённое не в журнале, undo мёртв. Фикс: журнал в `finally`. Тест: cancel_flag=[True] после первого чанка → журнал содержит реально удалённые.
7. **TypeError в настройках.** `get_styled_dialog` без обязательного `content` роняет «Очистить кэш» и «Контекстное меню». Фикс: дефолт `content=None` в components + вызовы. Тест: on_clear_cache не падает.
8. **scan_for_sample**: алиасы образца (тот же inode) исключаются, а не только точный путь.

## Блок B — корректность деструктивных операций
9. **C2 для клинера**: execute_clean сверяет size/mtime со снимком скана (verify_file_unchanged → в scanner.py, общий). Тест: файл изменён после скана → не удалён.
10. **confirm_move → _protect_originals** (сейчас «Переместить» увозит всю группу). Тест: все файлы группы выбраны → оригинал защищён.
11. **perform_move**: сбой удаления источника после успешной копии → копия удаляется (нет невидимых дублей); same-volume → атомарный `os.replace`; резервирование имени `O_CREAT|O_EXCL`. Тесты: lock на источнике → dest не остаётся; существующий dest не перезаписывается.
12. **ops_log undo**: файловые операции ВНЕ `_lock` (UI не фризит); `undone=True` только при полном восстановлении. Тест: частичный сбой → op НЕ undone, кнопка жива.
13. **hardlink**: краш между rename → backup возвращается на место при повторе; already-linked не журналируется. Тесты.
14. **load_history**: `isinstance(data, list)` — битый JSON не роняет скан-воркер. Тест: `{}` в файле → [].

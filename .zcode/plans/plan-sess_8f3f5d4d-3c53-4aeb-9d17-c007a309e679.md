# Полный аудит Duplicater: фиксы + тесты + инфраструктура + отчёт

## Итог аудита (кратко)
Duplicater — Python/Flet GUI-приложение для поиска дубликатов (Windows). Аудит выявил **34 проблемы**: 3 критических (безвозвратная потеря данных), 5 высоких (падение «Сравнения папок», небезопасное удаление), 12 средних, 14 низких. Плюс: тестов нет вообще, линтера нет, README нет, git-репозитория нет, версии зависимостей не зафиксированы. Все критические/высокие находки подтверждены чтением кода.

**Жёсткое ограничение от вас: никакие данные с компьютера не удалять.** Оно встроено в каждый этап ниже.

## Гарантии сохранности ваших данных (приоритет №1)
1. Все тесты работают **только** во временных каталогах pytest (`tmp_path`) — создают собственные файлы-приманки и удаляют только их. Ни один тест не сканирует реальные диски.
2. `tests/conftest.py` подменяет пути `scan_cache.db`, `operations_log.json`, `scan_history.json` на временные копии во временных каталогах — реальные файлы данных никогда не открываются на запись.
3. Проверка логики удаления/хардлинков — только на файлах, созданных тестом во временном каталоге.
4. До начала и после окончания всех работ — контрольные суммы (`scan_cache.db*`, `operations_log.json`, `scan_history.json`); в отчёт войдёт подтверждение, что они не изменились.
5. Git-репозиторий инициализируется с базовым коммитом **до** правок — полный откат в одну команду.

## Этап 2: Фиксы

### Критические (потеря данных)
- **C1 — хардлинк для визуально похожих фото.** В `run_scan(is_phash=True)` результаты идут в тот же `ResultsView` с активной кнопкой хардлинка, а `replace_with_hardlink` не проверяет байтовую идентичность → замена похожего (не идентичного) фото хардлинком безвозвратно теряет его контент. Фикс: (а) `ResultsView` получает флаг `allow_hardlink=False` для phash-результатов — кнопка скрыта; (б) в `hardlink_manager.replace_with_hardlink` — обязательная проверка size+полный хэш перед заменой (защита в глубину).
- **C2 — TOCTOU, удаление без перепроверки.** Удаление/хардлинк действует на пути, снятые при сканировании: если файл изменился за это время — удаляется уже не тот файл. Фикс: `ResultsView` передаёт вместе с путями (path, size, mtime) из `FileInfo`; воркер перед `os.remove`/`send2trash`/hardlink сверяет актуальные size/mtime, при расхождении — пропуск + запись в ошибки.
- **C3 — «Выделить всё»/«Инвертировать» wipes группу целиком.** Правила `all`/`invert` в `apply_smart_selection` выделяют и «оригинал». Фикс: гард «останется ≥1 копия» — при удалении файлы групп, где выделены все, кроме оригинала, защищаются; диалог подтверждения предупреждает о таких группах.

### Высокие
- **H1 — вкладка «Общие файлы» падает с KeyError.** `scanner.compare_folders` возвращает ключи `file_a/file_b/similarity/newer/larger`, а `compare_view` читает `name/path_a/path_b/size`. Фикс: привести вью к реальной схеме (+ бейджи «newer/larger» уже есть в данных).
- **H2 — fallback при ошибке сравнения с третьей, несовместимой схемой** (`main.py:300`) → KeyError, поток умирает, прогресс висит. Фикс: правильная схема `unique_a/unique_b/common/total_files` + показ ошибки в UI.
- **H3 — FilePicker не смонтированы на page** во всех 5 вью → выбор папок/файлов/экспорт могут не работать (след отладки `_probe_fp.py` это подтверждает). Сверю с исходником flet 0.86.5 в venv, смонтирую пикеры нужным API, проверю.
- **H4 — «Очистка мусора» удаляет навсегда без подтверждения.** Фикс: диалог подтверждения + опция «в корзину» + запись в журнал операций (как в ResultsView); убрать `desktop.ini` из `JUNK_FILENAMES` (легитимный файл Windows).
- **H5 — сбой корзины молча превращается в безвозвратное удаление.** `send2trash` упал → сейчас `os.remove`. Фикс: при сбое — НЕ удалять, записать ошибку.

### Средние (безопасные)
- **M1:** `ctypes` — `WinDLL("kernel32", use_last_error=True)`, `argtypes`, корректные коды ошибок.
- **M2:** `is_system_path` — сопоставление по целым компонентам пути от реальных системных корней (`%SystemRoot%`, `%ProgramFiles%`), а не подстроки; защита и для Windows на диске ≠ C:.
- **M3:** ключи групп pHash `f"Photo Group: {name}"` коллидируют по имени → кластеры теряются. Фикс: уникальный ключ (индекс/путь).
- **M4:** pHash-кластеризация O(n²) с дорогими попарными операциями → прекомпиляция хэшей в int + проверка отмены во внутреннем цикле.
- **M5:** `scan_for_sample` без префильтра по размеру хэширует каждый файл однопоточно, мимо кэша. Фикс: префильтр по размеру + SQLite-кэш.
- **M6:** остатки `.tmp_hl_*`/`.tmp_hl_backup_*` блокируют повторные хардлинки и никогда не чистятся. Фикс: зачистка остатков + честный учёт освобождённого места.
- **M7:** undo хардлинка удаляет дубликат ДО копии (сбой = файла нет) и выполняется в UI-потоке (фризы). Фикс: копия во врем имя → атомарная замена; undo в фоновом потоке.
- **M8:** ошибка сканирования дополнительно рапортует «Дубликаты не найдены» — ранний return, как в `run_sample_scan`.
- **M9:** «wasted space» считается как `(n-1)*size(оригинала)` — врёт для групп разных размеров. Фикс: сумма фактических размеров дубликатов.
- **M10:** парсер .lnk без `local_base_path_offset == 0` → валидные ярлыки помечаются битыми. Фикс: гард + учёт флагов LinkInfo.
